# Require Resumable Transfers for V1

Production v1 must support Resumable Transfers rather than requiring every interrupted Transfer to restart from the beginning. A v1 Resumable Transfer must survive temporary network loss and either app being closed and reopened, as long as the Sender still has the same file available and the Receiver keeps the partial download. "Same file" is defined by Content Identity, not filename, path, or modified time. If the Sender's source file content changes or is deleted, the Transfer becomes no-longer-resumable and requires a new Transfer Ticket. If the Sender moves the same file, Vegam asks the Sender to reselect it and continues only if Content Identity matches. This increases storage, integrity, and state-management complexity, but it is part of the production bar for large desktop file transfers.
