# Prefer Iroh Blobs After a Production Spike

Vegam prefers `iroh-blobs` for production v1 if a focused spike proves it can meet the v1 bar for 100 GB single-file Transfers, Resumable Transfers, Content Identity, and bounded memory usage. The spike must demonstrate an actual desktop-to-desktop transfer of a 100 GB file or sparse-file equivalent, bounded memory, verified Content Identity, resume after network loss, resume after Sender and Receiver app restart, manual pause/resume, Receiver Partial Downloads in the managed resume area, and failure when the Sender's content changes. Its content-addressed, verified transfer model aligns with Vegam's Content Identity and resume requirements; a custom Iroh stream protocol remains a fallback only if the latest `iroh-blobs` line cannot satisfy the production spike.
